**Demo/fallback mode:**
If `GEMINI_API_KEY` is absent or the API call fails, the application returns a pre-written fallback report clearly labelled `[DEMO MODE — LLM unavailable]`. Analysis and tables still render from real data; only the narrative section uses the fallback text.

## 5. CSV SCHEMA

### Required columns (exact names, case-insensitive after normalisation)

| Column | Type | Accepted values | Format |
|---|---|---|---|
| `date` | Date | Valid calendar date | `YYYY-MM-DD` (ISO 8601 preferred); also accept `DD/MM/YYYY`, `MM/DD/YYYY` — parsed with dateutil |
| `time` | Time | 24-hour time | `HH:MM` or `HH:MM:SS` — seconds ignored |
| `zone` | String | Any non-empty string | Normalise: strip whitespace, title-case |
| `species` | String | Any non-empty string | Normalise: strip whitespace, title-case |
| `incident_type` | String | Any non-empty string | Normalise: strip whitespace, title-case |
| `damage_description` | String | Any text, may be empty | Retain as-is; empty is a warning, not an error |
| `resolved` | Boolean-like | `yes`, `no`, `true`, `false`, `1`, `0` (case-insensitive) | Normalise to `Yes` / `No` |

### Optional columns (ignored if present, not required)
- `notes`, `reporter_name`, `location_detail`, `follow_up` — accepted silently, not analysed

### Missing value handling

| Field | If blank/null |
|---|---|
| `date` | **Block record** — row excluded, user warned |
| `time` | **Warn** — row excluded from time-of-day analysis only; still counted in all other analyses |
| `zone` | **Block record** — row excluded, user warned |
| `species` | **Block record** — row excluded, user warned |
| `incident_type` | **Block record** — row excluded, user warned |
| `damage_description` | **Warn** only — record kept |
| `resolved` | **Warn** — treated as "Unknown" in resolution analysis |

### Duplicate handling
Exact duplicate rows (all columns identical) → remove silently + show count in validation summary. Rows with same date/time/zone/species but different description → keep both (may be separate incidents).

### Minimum records: 5 (fewer than 5 → block analysis with message)
### Maximum practical file size: 5 MB / ~10,000 rows (MVP cap)
### Malformed CSV: If pandas cannot parse the file at all → block with message

### Whitespace normalisation: strip leading/trailing whitespace on all string fields
### Species/zone normalisation: strip + title-case (e.g., `  elephant ` → `Elephant`)

## 7. ANALYSIS LOGIC

All computations are performed by Python/pandas. **This is not AI.** Label it "automated analysis" in all user-facing text.

### Calculations

```python
# Reporting period
period_start = df['date'].min()   # earliest date in validated dataset
period_end   = df['date'].max()   # latest date in validated dataset
total_records = len(df)

# Incidents by species
species_counts = df['species'].value_counts()
species_pct    = (species_counts / total_records * 100).round(1)

# Incidents by zone
zone_counts = df['zone'].value_counts()
zone_pct    = (zone_counts / total_records * 100).round(1)

# Incidents by incident_type
type_counts = df['incident_type'].value_counts()
type_pct    = (type_counts / total_records * 100).round(1)

# Time brackets — applied only to rows where time is valid
def assign_bracket(t):
    h = t.hour
    if  6 <= h <= 11: return 'Morning (06:00–11:59)'
    elif 12 <= h <= 16: return 'Afternoon (12:00–16:59)'
    elif 17 <= h <= 20: return 'Evening (17:00–20:59)'
    else:               return 'Night (21:00–05:59)'

df_timed = df.dropna(subset=['time_parsed'])
df_timed['bracket'] = df_timed['time_parsed'].apply(assign_bracket)
bracket_counts = df_timed['bracket'].value_counts()
bracket_pct    = (bracket_counts / len(df_timed) * 100).round(1)
# Report base as % of timed records, not total records — disclose this

# Resolution status
resolved_counts = df['resolved'].value_counts()
resolved_pct    = (resolved_counts / total_records * 100).round(1)

# Unresolved by zone
unresolved_df    = df[df['resolved'] == 'No']
unresolved_zones = unresolved_df['zone'].value_counts()
```

### Time bracket boundary behaviour
- `17:00` → Evening (inclusive lower bound)
- `20:59` → Evening (inclusive upper bound)
- `21:00` → Night
- `05:59` → Night
- `06:00` → Morning
- Midnight `00:00` → Night

### Pattern identification (transparent rules, not ML)

```python
top_zone        = zone_counts.index[0]
top_zone_count  = zone_counts.iloc[0]
top_zone_pct    = zone_pct.iloc[0]

top_species      = species_counts.index[0]
top_species_pct  = species_pct.iloc[0]

peak_bracket     = bracket_counts.index[0]  # only if timed records >= 5
peak_bracket_pct = bracket_pct.iloc[0]

top_type         = type_counts.index[0]
top_type_pct     = type_pct.iloc[0]

unresolved_count = resolved_counts.get('No', 0)
unresolved_pct   = round(unresolved_count / total_records * 100, 1)

top_unresolved_zone = unresolved_zones.index[0] if len(unresolved_zones) > 0 else None
```

**Small sample guard:** If total_records < 20, all pattern statements are prefaced: `"Based on a small dataset ([n] records), the following patterns were observed — interpret with caution."`

**Zone concentration threshold:** Only describe a zone as having "the highest recorded concentration" if its count is at least 2 incidents. A single incident in a zone is reported as a count, not a concentration.

## 8. PATTERN-DETECTION LOGIC

The following plain-language statements are generated by Python (not the LLM) from the computed values. They are inserted into the prompt and also displayed on Screen 2.

```python
def build_pattern_statements(stats, total_records):
    stmts = []

    # Minimum record qualifier
    if total_records < 20:
        stmts.append(
            f"Note: This analysis is based on {total_records} records. "
            "Observed patterns may not be representative."
        )

    # Zone
    stmts.append(
        f"{stats['top_zone']} recorded the highest share of logged incidents "
        f"({stats['top_zone_count']} of {total_records}, {stats['top_zone_pct']}%)."
    )

    # Species
    stmts.append(
        f"{stats['top_species']} incidents represented the largest recorded species category "
        f"({stats['top_species_count']} of {total_records}, {stats['top_species_pct']}%)."
    )

    # Time of day (only if enough timed records)
    if stats['timed_records'] >= 5:
        stmts.append(
            f"{stats['peak_bracket']} was the most frequently recorded time period "
            f"({stats['peak_bracket_count']} of {stats['timed_records']} timed records, "
            f"{stats['peak_bracket_pct']}%)."
        )

    # Resolution
    stmts.append(
        f"{stats['unresolved_count']} incidents ({stats['unresolved_pct']}%) remain recorded as unresolved."
    )

    return stmts
```

**Language rules enforced throughout:**
- Use: "highest recorded concentration", "observed pattern", "largest share of logged incidents", "based on available records", "most frequently recorded"
- Do not use: "hotspot", "cause", "risk", "significant increase", "statistically significant", "proves", "indicates"
- Comparisons to prior month (if provided): "compared to the [n] incidents recorded in the previous period" — not "increase" or "decrease" unless explicitly framed as a recorded change

## 9. AI ARCHITECTURE

### What Python/pandas does
- Reads and validates the CSV
- Calculates all counts, percentages, and distributions
- Identifies top zone, top species, peak time bracket, unresolved count
- Generates plain-language pattern statements (using the template function above)
- Builds the structured prompt payload

### What the LLM does
- Receives the fully calculated, structured analysis results as input
- Converts those results into professional report prose
- Organises findings into the required section structure
- Generates appropriate, cautious mitigation *considerations* based only on the observed patterns
- Does NOT receive raw CSV data
- Does NOT receive any information beyond what Python calculated and explicitly provided

### Why this is a legitimate AI use case
Converting structured numerical findings into a professional, contextually appropriate narrative — with the correct tone, qualified language, sectioned structure, and practical (non-directive) mitigation suggestions — is genuinely a language task. A fixed template cannot handle variable species combinations, zone patterns, and time patterns in ways that read as coherent professional prose. The LLM adds genuine value in the narrative generation step. All factual claims in the output trace to Python-calculated inputs.

### Data flow to LLM
```
Python produces:
{
  "period": "October 2025",
  "total_records": 87,
  "excluded_records": 3,
  "timed_records": 84,
  "species": [{"name": "Elephant", "count": 47, "pct": 54.0}, ...],
  "zones": [{"name": "Zone D", "count": 31, "pct": 35.6}, ...],
  "types": [{"name": "Crop Raid", "count": 58, "pct": 66.7}, ...],
  "brackets": [{"name": "Evening (17:00–20:59)", "count": 37, "pct": 44.0}, ...],
  "resolved": {"Yes": 53, "No": 34, "Unknown": 0},
  "pattern_statements": ["Zone D recorded...", "Elephant incidents..."],
  "small_sample": false
}
```
This JSON is serialised and inserted into the prompt. The LLM never sees the raw CSV.

## 12. RESPONSIBLE AI IMPLEMENTATION

| Risk | Technical mitigation | User-facing disclosure |
|---|---|---|
| **Hallucination** | LLM receives only pre-calculated structured data; prompt explicitly forbids adding facts not provided | "All observations are based solely on the uploaded incident records" |
| **Small sample sizes** | Python flags `small_sample = True` if < 20 records; prompt instructs LLM to reflect caution; Screen 2 shows warning | "Dataset contains [n] records. Patterns should be interpreted cautiously." |
| **Incomplete data** | Excluded records counted and shown to user; disclosed in report Data Coverage section | "Based on [n] valid records. [n] records excluded during validation." |
| **Incorrect data** | Validation catches malformed entries; user sees what was excluded | Warning list on Screen 1 |
| **Misleading correlations** | Prompt forbids causation language; pattern statements use "observed distribution" language | Pattern statement language: "recorded concentration", not "cause" |
| **False causation** | Explicit in prompt: "Never state or imply causation" | Report uses "observed pattern" / "recorded distribution" throughout |
| **Over-reliance on AI** | Responsible AI notice on Screen 3, in the generated report, and in the exported document | "AI-GENERATED DRAFT — HUMAN REVIEW REQUIRED" — prominent, always visible |
| **Privacy** | No data stored after session; no external logging; CSV is processed in memory only | Privacy note in help text: "Uploaded data is processed in your session only and not stored." |
| **Sensitive wildlife locations** | MVP uses no map, no GPS — location data is zone names only, no coordinates | Not applicable for MVP; note for production: avoid publishing precise GPS coordinates |
| **Sensitive community information** | `damage_description` is retained but not sent to LLM (only counts and patterns are sent) | Privacy note; production recommendation: remove identifiable reporter details before upload |
| **Enforcement misuse** | Prompt forbids enforcement recommendations; report explicitly states "not directives" | "Suggested mitigation considerations are not directives and do not constitute official guidance." |
| **Biased/incomplete reporting** | Report discloses number of excluded records; pattern statements qualified with "based on available records" | Data Coverage section; qualification language throughout |

### Phase 2 — CSV Validation

**Build:** `core/upload.py`
- `validate_csv(file_object)` function
- Column presence check
- Date parsing with `dateutil.parser.parse` in a `try/except`
- Time parsing with `datetime.strptime` in a `try/except`

- Duplicate removal
- Warning/error accumulation
- Returns structured result dict

**Files affected:** `core/upload.py`, `app.py` (add `/upload` route)
